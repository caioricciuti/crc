An editor's first job is not to lose or damage your text. This page is how crc
does that.

## Saving

<div class="crc-keys">
  <div><span>Save</span><span><kbd>⌘</kbd><kbd>S</kbd></span></div>
  <div><span>Save as</span><span><kbd>⌘</kbd><kbd>⇧</kbd><kbd>S</kbd></span></div>
</div>

Ordinary saves write a new file and atomically swap it in. The file's
**mode**, **hard links** and **symlink targets** are preserved. Keeping
hard links or saving in a directory that cannot replace entries can require
an in-place write; those saves do not have atomic replacement's guarantees.

**File › Revert to Saved** throws away your edits and goes back to what is on
disk.

## When another program changes a file

crc watches the project folder.

| The tab is… | What happens |
|---|---|
| Clean | It reloads with the new contents. |
| Dirty | Nothing changes until you save. Then crc asks: **Overwrite**, **Cancel** or **Reload**. |
| Deleted on disk | The tab is marked unsaved, so closing it asks first. |

This is what makes [Claude Code](/docs/features/claude-code/), formatters and
`git checkout` safe to run next to open tabs.

## Closing and quitting

Closing a tab or quitting crc with unsaved changes asks first.

## Crash recovery

On a Rust panic, crc attempts to write unsaved documents to
`~/Library/Application Support/crc/recovery/`. On the next start it offers
recoverable entries. This cannot guarantee recovery from every process or
system failure.

<Aside type="tip" title="Plain files, on purpose">
  Each crash gets its own folder holding, for each unsaved document, `<n>.txt`
  with its text and `<n>.path` with where it came from. If crc cannot start at
  all, your work is still there to open with anything.
</Aside>

Recovery covers crashes in crc's own code. It does not cover a power cut.

## Encodings and line endings

crc keeps what the file had:

- UTF-8, with or without a byte-order mark
- UTF-16 with a BOM
- Windows-1252
- LF, CRLF and every other line ending

The encoding and line ending are shown in the status line.

## Very large files

| Size | Behaviour |
|---|---|
| Up to 512 MB | Opens for editing; loading, parsing and indexing still depend on the file. |
| Over 512 MB | Opens **read-only**, and says why. |
| Over 2 GB | Refused, and says why. |

Lines too long to shape quickly are drawn without shaping, and the status
line says so while one is on screen.

## Local versions and undo

crc keeps bounded local versions and can restore undo/redo across restarts
when the file on disk still matches. See
[File history and local versions](/docs/features/history/) for retention,
secret exclusions, restoring text and clearing history.

CSV/TSV editing and the read-only DuckDB previews are described in
[Data tables and SQL queries](/docs/features/data-tables/).
