## Platform

- **macOS on Apple Silicon only**, macOS 14 or later. There is no Intel build
  in the alpha.
- **No Linux or Windows, deliberately.** crc talks to Metal and CoreText
  directly; a port would mean writing a second backend from scratch. See
  [Architecture](/docs/reference/architecture/).

## Languages

- **Highlighting covers the [listed languages](/docs/features/syntax-highlighting/).**
  Each grammar is vendored generated C pinned in `third_party/CHECKSUMS`. SQL is
  not in the alpha.
- **Five language-server integrations.** Code actions depend on what the
  installed server supplies; crc does not bundle language servers.

## Editor

- **No minimap.**
- **Markdown styling has edges.** Non-ASCII lines do not draw italic in its
  own face, bold uses a doubled regular face, and right-to-left lines keep
  syntax visible. Wrapped rows break by raw text width, including hidden
  syntax. Headings use the body font size.
- **Panes are a way of looking.** A file is open in one pane at a time, and a
  restored session puts every pane's files into one pane.
- **Bounded by design.** Project search skips files over 2 MiB and shows the
  first 500 matches. The bracket matcher counts its own pair only and does not
  skip strings or comments.
- **Text input is new.** Dead keys and IME go through macOS text input and
  need wider testing across layouts.

## Git

- **Gutter marks compare with HEAD**, not the index, and stop at 2 MiB.
- **Hunk staging covers tracked text changes**; other change types use
  whole-file actions.
- **History is per file.** There is no repository log or commit graph.
  Diverged pulls can rebase or merge; starting an arbitrary branch merge or
  rebase is still a terminal operation. crc resolves conflicts, aborts merge
  or rebase, and continues a rebase.
- **Conflict markers are Git's default seven characters.** A custom
  `conflict-marker-size` is not recognised, and files over 16 MiB are not
  scanned for conflicts.

## Files

- Files over **512 MB** open read-only; files over **2 GB** are refused. Both
  say why.
- Crash recovery covers crashes in crc's own code, not a power cut.
- Local history keeps bounded versions of files up to 2 MiB, with secret
  exclusions and retention limits. It is not a complete backup.
- Office documents remain read-only Quick Look previews. DuckDB data
  grids are bounded, read-only snapshots, not full database editing.

## Updates and extensions

- **Updates require your action.** The daily check downloads nothing;
  Check for Updates and Restart to Update download, verify and install
  when you ask. Installation needs write access to the app location.
- **Extensions are narrow.** Capabilities cover selection/document text and
  a restricted preview page, not filesystem, network or process access.
  See [Extensions](/docs/features/extensions/).

## Agents and MCP

- **Agent undo needs a copy from before the write.** crc-started Claude
  Write/Edit hooks can provide one. Shell writes and unhooked agents are
  keep-only. The separate Review page has been removed.
- **Sessions after reboot are replacements.** The original process and
  scrollback are lost; Claude resume chooses the folder's latest
  conversation. A session reattached after an app restart needs `/ide`
  to restore the IDE connection.
- **Remote workspaces do not open remote files in the editor** or run
  crc's review hooks on the host. Host CPU/disk are not monitored.
- **MCP supports the core transports.** No OAuth login, server sampling,
  elicitation or roots requests, or interactive MCP Apps rendering.
  `crc --mcp` reads disk and index state, not unsaved buffers.
